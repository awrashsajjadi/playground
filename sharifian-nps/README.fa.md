# نظرسنجی NPS شریفیان

فرم سه‌مرحله‌ای نظرسنجی برای حدود ۵۰۰ مشتری عمده، پنل ادمین (ورود لیست مشتریان، لینک کانال‌ها، خروجی اکسل)، داشبورد تحلیلی با گزارش چاپی، و هشدار فوری منتقدان در بله.

همه‌چیز روی همین سرور است: فونت، نمودار و اسکریپت‌ها self-hosted هستند و صفحه‌ها به هیچ سرویس خارجی (گوگل، CDN، reCAPTCHA) درخواست نمی‌دهند. دیتابیس یک فایل SQLite است.

## ۱. اجرای محلی در ۳ دستور

پیش‌نیاز: [Node.js](https://nodejs.org) نسخه‌ی ۲۲٫۱۸ یا جدیدتر (یا ۲۴). نسخه را با `node -v` ببینید. ابزار دیگری لازم نیست؛ ویندوز، مک و لینوکس فرقی ندارند.

کد را بگیرید (با git یا دانلود ZIP از گیت‌هاب) و داخل پوشه‌ی `sharifian-nps` این سه دستور را بزنید:

```bash
npm install
```

```bash
npm run seed:demo
```

```bash
npm run dev
```

- دستور دوم اختیاری است: ۵۰۰ مشتری و ۱۸۰ پاسخ نمایشی می‌سازد تا داشبورد خالی نباشد. با `npm run seed:clear` پاک می‌شود و به داده‌ی واقعی دست نمی‌زند.
- `npm run dev` بعد از بالا آمدن سه آدرس چاپ می‌کند:
  - **فرم:** `http://localhost:3000`
  - **داشبورد:** `http://localhost:3000/admin/dashboard`، با رمز `admin` در حالت توسعه.
  - **روی گوشی:** آدرسی مثل `http://192.168.1.20:3000`، اگر گوشی به همان وای‌فای وصل باشد. ویندوز ممکن است برای Node.js اجازه‌ی شبکه بخواهد؛ تأیید کنید.
- در حالت توسعه، اگر تاریخ کمپین را تنظیم نکرده باشید، کمپینی فرض می‌شود که ۵ روز پیش شروع شده و ۲ روز دیگر تمام می‌شود. برای امتحان یک تنظیم (مثلاً تاریخ‌ها یا ربات بله)، فقط همان متغیرها را در فایل `.env` کنار `package.json` بگذارید و سرور را دوباره اجرا کنید. `.env.example` نمونه‌ی production است و `NODE_ENV=production` دارد.
- **حالت آزمایشی:** اگر فرم را در همان مرورگری پر کنید که با آن وارد پنل شده‌اید، پاسخ «آزمایشی» حساب می‌شود و در آمار نمی‌آید. برای دیدن پاسخ خودتان در داشبورد، فرم را در پنجره‌ی ناشناس یا روی گوشی پر کنید.

## ۲. استقرار روی لیارا (قدم‌به‌قدم)

برنامه روی پلتفرم **Docker** لیارا اجرا می‌شود. تنظیماتش در [`liara.json`](liara.json) است:
- **پورت:** ۳۰۰۰
- **دیسک:** یک دیسک پایدار به نام `data` که به `/data` وصل می‌شود.

دیتابیس و بکاپ‌های خودکار روی همین دیسک‌اند و با هر استقرار دوباره پاک نمی‌شوند.

> نام دکمه‌ها و منوهای پنل لیارا ممکن است با این متن کمی فرق کند؛ مرجع نهایی [مستندات لیارا](https://docs.liara.ir) است.

**۱. ساخت برنامه.**
- در پنل لیارا یک برنامه‌ی جدید با پلتفرم **Docker** بسازید.
- نام برنامه را `sharifian-nps` بگذارید. اگر این نام آزاد نبود، نام دیگری بگذارید و همان را در فیلد `app` فایل `liara.json` بنویسید.
- کوچک‌ترین پلن کافی است. ۵۰۰ مشتری بار زیادی نیست؛ تست بار با ۱۰۰ کاربر هم‌زمان p95 زیر ۱۰۰ میلی‌ثانیه داد.

**۲. دیسک.**
- در صفحه‌ی برنامه، بخش دیسک‌ها، یک دیسک با نام **`data`** و حجم ۱ گیگابایت بسازید.
- نام دیسک باید دقیقاً با `liara.json` یکی باشد. مسیر اتصالش (`/data`) در همان فایل آمده است.

**۳. متغیرهای محیطی.** در تنظیمات برنامه این‌ها را بگذارید (جزئیات در [بخش ۷](#env)):

| متغیر | مقدار |
|---|---|
| `ADMIN_PASSWORD` | رمز پنل؛ حداقل ۱۲ نویسه |
| `SESSION_SECRET` | یک رشته‌ی تصادفی ۶۴ نویسه‌ای؛ برای ساختنش دستور زیر جدول را بزنید |
| `SURVEY_OPENS_AT` | `2026-11-08T08:00:00+03:30` |
| `SURVEY_CLOSES_AT` | `2026-11-14T23:59:59+03:30` |
| `PUBLIC_BASE_URL` | `https://nazar.sharifianshop.com` |
| `DETRACTOR_WEBHOOK_URL` | `https://tapi.bale.ai/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>` |

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`PORT`، `DATABASE_PATH` و `NODE_ENV` لازم نیست؛ داخل ایمیج تنظیم شده‌اند. `TRUST_PROXY` را هم به پیش‌فرض بسپارید.

**۴. استقرار.** ابزار خط فرمان لیارا را نصب کنید، وارد شوید و از داخل پوشه‌ی `sharifian-nps` استقرار بدهید:

```bash
npm install -g @liara/cli
```

```bash
liara login
```

```bash
liara deploy
```

لیارا ایمیج را از روی `Dockerfile` می‌سازد. در لاگ برنامه باید `Server listening` و `daily backups → /data/backups` دیده شود. آدرس موقت برنامه (`https://<نام-برنامه>.liara.run/healthz`) باید `{"ok":true}` برگرداند.

**۵. زیردامنه و SSL.**
1. در بخش دامنه‌های برنامه، `nazar.sharifianshop.com` را اضافه کنید.
2. لیارا رکوردی را که باید در DNS بسازید نشان می‌دهد (معمولاً CNAME). همان را در DNS دامنه‌ی `sharifianshop.com` بسازید.
3. بعد از تأیید دامنه، گواهی SSL رایگان را فعال کنید و انتقال خودکار به HTTPS را روشن کنید.
4. در آخر `https://nazar.sharifianshop.com/healthz` را باز کنید.

**۶. به‌روزرسانی.** بعد از هر تغییر در کد یا فایل‌های `config/` دوباره `liara deploy` بزنید. داده روی دیسک می‌ماند.

## ۳. استقرار روی VPS با Docker Compose و Caddy

برای سروری که Docker و Compose دارد. Caddy گواهی HTTPS را خودش می‌گیرد و تمدید می‌کند.

پیش‌نیازها:
- پورت‌های ۸۰ و ۴۴۳ باز باشد.
- یک رکورد **A** برای `nazar.sharifianshop.com` به IP سرور اشاره کند.

```bash
git clone -b claude/new-session-w5sy21 https://github.com/awrashsajjadi/playground.git
```

```bash
cd playground/sharifian-nps
```

```bash
cp .env.example .env
```

حالا `.env` را با ویرایشگر باز کنید و مقدارها را پر کنید (همان جدول لیارا). اگر دامنه چیز دیگری است، `DOMAIN=...` را هم اضافه کنید. بعد:

```bash
docker compose up -d --build
```

- **لاگ‌ها:** `docker compose logs -f app`
- **به‌روزرسانی:** `git pull` و دوباره `docker compose up -d --build`.
- **داده:** دیتابیس و بکاپ‌ها در پوشه‌ی `./data` کنار همین فایل‌ها هستند. این پوشه را هرگز پاک نکنید.
- **سرور در ایران:** Docker Hub آی‌پی‌های ایران را می‌بندد. یک میرور داخلی را در `/etc/docker/daemon.json` بگذارید و `systemctl restart docker` بزنید. آدرس میرور را از ارائه‌دهنده‌ی سرور بپرسید؛ میرور آروان یک نمونه است:

  ```json
  { "registry-mirrors": ["https://docker.arvancloud.ir"] }
  ```

- **میرور npm:** اگر npm هم کند یا بسته بود، آدرس یک میرور npm را هنگام build بدهید:

  ```bash
  docker compose build --build-arg NPM_REGISTRY=https://mirror.example/npm/
  ```

## ۴. چک‌لیست روز قبل از کمپین

| | کار | کجا |
|---|---|---|
| ☐ | **پاک کردن داده‌ی دمو** (اگر برای نمایش ساخته بودید). بنر قرمز دمو باید از پنل برود. | پنل ← خانه ← «پاک کردن داده‌ی دمو» (یا `npm run seed:clear`) |
| ☐ | **ورود لیست واقعی مشتریان.** خطاهای پیش‌نمایش را بخوانید و فقط بعد تأیید کنید. نکته‌های اکسل زیر جدول آمده است. | پنل ← لیست مشتریان |
| ☐ | **تاریخ باز و بسته شدن** با ساعت تهران (`+03:30`). بعد از تغییر، برنامه را دوباره اجرا کنید. خانه‌ی پنل «شروع تا … دیگر» را نشان می‌دهد. | `SURVEY_OPENS_AT` و `SURVEY_CLOSES_AT` |
| ☐ | **رمز و کلیدها:** `ADMIN_PASSWORD` قوی، `SESSION_SECRET` تصادفی، `PUBLIC_BASE_URL` با https. | متغیرهای محیطی |
| ☐ | **یک ثبت آزمایشی از هر کانال**؛ مراحلش زیر جدول آمده است. | پنل ← لینک کانال‌ها ← «لینک‌های آزمایشی» |
| ☐ | **پاک کردن ثبت‌های آزمایشی** بعد از امتحان. | پنل ← خانه ← «حذف همه‌ی ثبت‌های آزمایشی» |
| ☐ | **بکاپ:** یک بکاپ دانلود کنید و جای امن نگه دارید. در خانه‌ی پنل خط «بکاپ خودکار روزانه» را ببینید. | پنل ← خانه ← «دانلود بکاپ» |
| ☐ | **لینک‌های واقعی** هر کانال و هر کارشناس را آماده کنید. | پنل ← لینک کانال‌ها |
| ☐ | **سلامت:** `https://nazar.sharifianshop.com/healthz` باید `{"ok":true}` برگرداند. | مرورگر |

**ثبت آزمایشی از هر کانال:**
1. هر لینک آزمایشی را از همان کانال (پیامک، واتساپ، بله، …) برای خودتان بفرستید.
2. لینک را روی گوشی باز کنید و یک امتیاز ۶ یا کمتر ثبت کنید.
3. پیام 🧪 باید در گروه بله برسد.

لینک آزمایشی قبل از شروع کمپین هم کار می‌کند و پاسخش در آمار نمی‌آید.

**نکته‌های اکسل برای لیست مشتریان:**
- **صفر اول موبایل:** اکسل صفر اول شماره‌ها را حذف می‌کند (`9121234567`). برنامه این را خودش درست می‌کند. با این حال بهتر است قبل از وارد کردن شماره‌ها، ستون موبایل را **Text** کنید، تا شماره به شکل علمی (`9.12E+09`) هم ذخیره نشود.
- **نوع فایل:** فایل را با «CSV UTF-8» ذخیره کنید. «CSV» معمولی اکسل فارسی (windows-1256) هم قبول است.
- **سرستون‌ها:** فقط ستون `mobile` (یا «موبایل») اجباری است. فایل نمونه در همان صفحه‌ی لیست مشتریان است.

## ۵. بکاپ

بکاپ سه لایه دارد (D33):

1. **خودکار و روزانه، داخل خود برنامه.**
   - روزی یک بار یک نسخه‌ی سالم در `/data/backups/daily-YYYY-MM-DD.db` ساخته می‌شود (تاریخ تهران) و ۷ نسخه‌ی آخر می‌ماند.
   - به cron نیازی ندارد و روی لیارا هم کار می‌کند.
   - خانه‌ی پنل زمان آخرین نسخه را نشان می‌دهد.
2. **دانلود از پنل** («دانلود بکاپ»).
   - این تنها نسخه‌ای است که بیرون از سرور نگه داشته می‌شود.
   - در روزهای کمپین، هر شب یک بار دانلود کنید.
3. **اسکریپت `scripts/backup.sh` با `sqlite3 .backup`**، برای cron روی VPS.
   - نسخه را در `/data/backups/manual-<زمان UTC>.db` می‌سازد.
   - با `integrity_check` سالم بودنش را بررسی می‌کند و ۷ نسخه‌ی آخر را نگه می‌دارد. تعدادشان با `BACKUP_KEEP` تغییر می‌کند.

   ```bash
   docker compose exec -T app sh scripts/backup.sh
   ```

   - برای اجرای هر شب ساعت ۲۳:۳۰، این خط را با `crontab -e` اضافه کنید (مسیر پروژه را درست بگذارید):

   ```text
   30 23 * * * cd /opt/playground/sharifian-nps && docker compose exec -T app sh scripts/backup.sh >> backup.log 2>&1
   ```

   - **اگر داخل ایمیج sqlite3 نبود:** ایمیج ابزار `sqlite3` را فقط وقتی دارد که سرور build به مخزن دبیان دسترسی داشته باشد. در غیر این صورت `sqlite3` را روی خود سرور نصب کنید و اسکریپت را از همان‌جا اجرا کنید:

   ```bash
   DATABASE_PATH=./data/nps.db sh scripts/backup.sh
   ```

همه‌ی فایل‌های بکاپ یک فایل مستقل‌اند و فایل `-wal` یا `-shm` کنارشان لازم نیست.

**برگرداندن بکاپ:**
1. برنامه را متوقف کنید (`docker compose stop app`؛ روی لیارا از پنل).
2. فایل بکاپ را جای `/data/nps.db` بگذارید و اگر `nps.db-wal` و `nps.db-shm` هست پاکشان کنید.
3. برنامه را دوباره اجرا کنید.

## ۶. ویرایش متن‌ها، گزینه‌ها و موضوع‌ها بدون دست زدن به کد

همه‌ی متن‌ها در دو فایل JSON هستند. برنامه هنگام شروع هر دو را بررسی می‌کند. اگر کلیدی جا افتاده یا JSON خراب شده باشد، بالا نمی‌آید و مشکل را به فارسی می‌گوید؛ پس فایل خراب هیچ‌وقت به دست مشتری نمی‌رسد. بعد از ویرایش:
- **لیارا:** `liara deploy`
- **VPS:** `docker compose up -d --build`
- **محلی:** `npm run dev`

**[`config/survey.fa.json`](config/survey.fa.json):** همه‌ی متن‌های فرم و پنل.

| کلید | چه چیزی را عوض می‌کند |
|---|---|
| `intro`، `step1.question`، `step1.lowLabel`/`highLabel` | متن خوشامد، سؤال اصلی و برچسب دو سر مقیاس |
| `step2.titles.promoter`/`passive`/`detractor` | عنوان گام ۲ بر اساس امتیاز (۹–۱۰، ۷–۸، ۰–۶) |
| `drivers` | چیپ‌های دلیل: `{ "id": "price", "label": "قیمت" }` |
| `step3.*` | متن موبایل، اجازه‌ی تماس و حریم خصوصی |
| `thanks.*`، `states.*`، `errors.*` | صفحه‌ی تشکر، «به‌زودی»، «بسته شد»، «تکراری» و پیام‌های خطا |
| `channels` | نام کانال‌ها: `"sms": "پیامک"` |
| `reps` | نام کارشناس‌ها: `"r01": "سارا احمدی"` (لینک با `&rep=r01`) |

- **`label` و متن‌ها:** هر وقت خواستید عوض کنید.
- **`id` چیپ‌ها و کلید کانال‌ها:** بعد از شروع کمپین عوض نکنید. با پاسخ‌ها ذخیره شده‌اند و در لینک‌ها هستند. چیپ تازه را با `id` تازه اضافه کنید.
- **ترتیب چیپ‌ها:** برای هر مشتری تصادفی است تا ترتیب روی جواب اثر نگذارد.

**[`config/themes.json`](config/themes.json):** موضوع‌های تحلیل متن نظرها (بخش ۸ داشبورد).

```json
{ "id": "delivery", "label": "ارسال و تحویل",
  "keywords": ["دیر", "تاخیر", "ارسال"], "exact": [], "exclude": ["دیروز"] }
```

- **`keywords`:** با ابتدای کلمه می‌خورد. مثلاً «دیر» با «دیرتر» هم می‌خورد، ولی با «مدیر» نه.
- **`exact`:** فقط با خود کلمه می‌خورد.
- **`exclude`:** کلمه‌هایی که نباید حساب شوند.
- **یکسان‌سازی:** ی/ک عربی و نیم‌فاصله خودکار یکسان می‌شوند.

بعد از تغییر این فایل، برچسب نظرهای قبلی هم هنگام شروع برنامه دوباره ساخته می‌شود.

## ۷. متغیرهای محیطی

نمونه‌ی کامل در [`.env.example`](.env.example) است. در production هر متغیر الزامی که نباشد، برنامه بالا نمی‌آید و فهرست کمبودها را چاپ می‌کند.

| متغیر | الزامی؟ | توضیح |
|---|---|---|
| `ADMIN_PASSWORD` | بله | رمز پنل؛ حداقل ۱۲ نویسه. مقایسه‌ی رمز constant-time است و بعد از ۱۰ تلاش اشتباه در ۱۵ دقیقه ورود قفل می‌شود. |
| `SESSION_SECRET` | بله | حداقل ۳۲ نویسه‌ی تصادفی؛ امضای کوکی، توکن فرم و هش IP |
| `SURVEY_OPENS_AT` / `SURVEY_CLOSES_AT` | بله | با منطقه‌ی زمانی، مثل `2026-11-08T08:00:00+03:30` |
| `PUBLIC_BASE_URL` | بله | فقط دامنه، مثل `https://nazar.sharifianshop.com` (برای لینک‌ها و پیام بله) |
| `DETRACTOR_WEBHOOK_URL` | نه | ربات بله برای هشدار فوری منتقد (امتیاز ۶ و کمتر) |
| `RATE_LIMIT_PER_HOUR` | نه | پیش‌فرض ۱۰ ثبت در ساعت برای هر IP؛ `0` یعنی خاموش |
| `TRUST_PROXY` | نه | پیش‌فرض `true` (لیارا). پشت Caddy مقدار `1` است (در `docker-compose.yml` تنظیم شده) |
| `DATABASE_PATH` | نه | پیش‌فرض `/data/nps.db` در ایمیج |
| `BACKUP_DIR` | نه | پیش‌فرض پوشه‌ی `backups` کنار دیتابیس |
| `CONFIG_DIR` | نه | پوشه‌ی دیگری برای `survey.fa.json` و `themes.json` |
| `DOMAIN` | فقط VPS | دامنه‌ی Caddy؛ پیش‌فرض `nazar.sharifianshop.com` |

<a id="troubleshooting"></a>

## ۹. رفع اشکال

- **«پیکربندی نامعتبر است»** هنگام شروع: فهرست زیرش دقیقاً می‌گوید کدام متغیر یا کدام کلید config مشکل دارد.
- **فرم «به‌زودی» یا «بسته شد» نشان می‌دهد:** تاریخ‌ها و منطقه‌ی زمانی (`+03:30`) را بررسی کنید.
- **«از این شبکه … ثبت‌های زیادی انجام شده»:** محدودیت ضد اسپم است (۱۰ در ساعت برای هر IP).
  - اگر همه‌ی کاربران این پیام را می‌بینند، برنامه IP واقعی را نمی‌بیند و `TRUST_PROXY` را باید بررسی کرد.
  - اگر در یک دفتر چند نفر از یک اینترنت ثبت می‌کنند، `RATE_LIMIT_PER_HOUR` را بالاتر ببرید.
- **پاسخ خودم در داشبورد نیست:** احتمالاً در همان مرورگرِ پنل پر شده و «آزمایشی» است ([بخش ۱](#local)).
- **`npm install` خطای node-gyp یا Python می‌دهد:** فایل `.npmrc` پروژه باید کنار `package.json` باشد. آن فایل کامپایل را خاموش می‌کند، چون باینری آماده‌ی SQLite همراه بسته است.
